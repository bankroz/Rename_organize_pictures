# Photo & Video Renamer v2.4

照片和视频批量按日期重命名工具。自动从多种来源提取拍摄时间，统一命名为 `YYYY.MM.DD_HHMM` 格式。

**v2.4**：新增小红书 Camera_XHS_ Unix 毫秒时间戳提取，智能发现模式支持 Unix 时间戳自动检测

---

## 架构流程

```
用户双击 launch.bat (GBK编码, CMD原生稳定)
          │
          ├─ 检查 Python → 安装指引
          ├─ 选择模式（预览/执行/副本整理/自定义）
          ├─ 输入或拖放文件夹路径
          │
          ▼
python photo_renamer.py -s <文件夹> -m <模式>
          │
          ├─ DateExtractor    日期提取引擎（4级优先级链）
          │    ├─ EXIF DateTimeOriginal  ← 相机写入，最准确
          │    ├─ 文件名日期（18种模式） ← patterns.json 配置
          │    ├─ Unix 时间戳（10位/13位 + App前缀）
          │    └─ 文件修改时间           ← 最终兜底
          │
          ├─ PatternDiscoverer  智能模式发现（--discover）
          │    6阶段启发式扫描 → 生成建议 JSON 条目
          │
          ├─ PhotoRenamer      重命名引擎
          │    ├─ scan_files()       扫描所有媒体文件
          │    ├─ process()          冲突处理 + 邻近slot分配
          │    └─ execute()          原地重命名 / 复制到 output
          │
          └─ run_with_timeout()  全链路 IO 超时保护
               ThreadPoolExecutor, 默认15s, 可环境变量调整
```

## 环境要求与安装依赖

以下是在 **全新 Windows 电脑** 上从零配置运行本工具的全部步骤。

### 1. 安装 Python

本工具需要 **Python 3.8 或更高版本**。

**推荐方式（Microsoft Store）**：
- 打开 Microsoft Store，搜索 "Python 3.12" 或 "Python 3.13"，点击安装
- Store 版本会自动配置 PATH，安装后无需额外操作

**备选方式（官网安装包）**：
1. 访问 https://www.python.org/downloads/ ，下载最新 Windows installer
2. 运行安装程序，**务必勾选 "Add Python to PATH"**（底部复选框）
3. 点击 "Install Now" 完成安装

**验证安装**（安装完成后，打开命令提示符或 PowerShell）：

```cmd
python --version
```

应输出类似 `Python 3.12.x` 的信息。如果提示找不到 python 命令，重启电脑后再试。

### 2. 安装 Pillow（EXIF 读取，强烈推荐）

Pillow 用于读取照片的 EXIF 拍摄时间，是唯一需要额外安装的第三方包。缺失时程序仍可运行，但会跳过所有图片的 EXIF 信息。

```cmd
pip install Pillow
```

验证安装：

```cmd
python -c "from PIL import Image; print('Pillow OK')"
```

### 3. 下载本工具

将以下文件放到同一个文件夹即可：

```
图片重命名整理/
├── photo_renamer.py    # 核心脚本（DateExtractor + PhotoRenamer + CLI）
├── launch.bat           # Windows 交互式启动器（GBK编码，中文菜单）
├── patterns.json        # 日期模式配置文件（18种模式，可手动编辑）
└── README.md            # 本说明（使用文档）
```

> `.workbuddy/` 和 `测试集/` 目录为本地开发数据，部署时不需要复制。

**无需安装其他依赖**——Python 标准库已覆盖 argparse、csv、re、shutil 等全部功能。

### 4. （可选）HEIC 照片支持

如果你的照片中有 `.heic` 格式（iPhone 默认格式），需要额外安装 HEIC 解码插件：

```cmd
pip install pillow-heif
```

## 功能特性

- **4 级日期提取优先级**：EXIF → 文件名日期 → Unix 时间戳 → 文件修改时间
- **18 种文件名模式自动识别**：覆盖主流相机、手机、微信、华为、HwVideoEditor、faceu 等设备和应用
- **可编辑模式配置 (JSON)**：`patterns.json` 文件手动添加/修改日期格式规则，即改即生效
- **智能模式发现 (`--discover`)**：自动扫描未识别文件中的潜在日期格式，生成建议条目供审核
- **启发式日期推断**：空格、中划线、下划线、点、斜杠等分隔符的 Y-M-D / D-M-Y / 紧凑型组合
- **渐进式 EXIF 读取**：只下载文件头部（256KB），无 EXIF 立即回退，节省网络 I/O
- **网络盘抗卡顿**：全链路超时保护（EXIF 读取 / stat / 复制 / 重命名），适合群晖等 NAS
- **实时进度条**：终端内联进度条，显示处理进度、耗时、超时跳过数
- **重复处理保护**：检测已重命名目录，执行模式下自动中止并提示，防止视频时分信息丢失
- **18 种文件名模式**：含 4 种自有输出格式的完整匹配，确保已重命名文件时间不变
- **哈希文件名防误判**：32 字符以上的哈希类文件名自动跳过时间戳匹配
- **智能冲突处理**：同名文件分钟自动 +1，含级联碰撞保护
- **预览模式**：不改文件，输出对照表（CLI + CSV）
- **执行模式**：原地重命名 / 复制到 output 目录
- **自定义格式**：4 种预设 + Python strftime 自由组合
- **图片 + 视频全支持**：38 种格式（RAW、HEIC、MP4、MOV 等）
- **bat 启动器**：双击即可使用的交互式菜单（中文界面，GBK 编码）

## 日期提取优先级链

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | EXIF DateTimeOriginal | 相机/手机写入的原始拍摄时间，最准确 |
| 2 | 文件名日期 | 自动识别 18 种模式（见下表） |
| 3 | Unix 时间戳 | 文件名中的 13 位毫秒或 10 位秒级时间戳 |
| 4 | 文件修改时间 | 以上全部失败时的兜底方案 |

| 7. YYYY-MM-DD\_HHMM | `2025-12-31_2359` | — |
| 8. YYYYMMDD-HHMMSS | `20240817-182522` | — |
| 9. YYYY-MM-DD-HH-MM-SS | `2024-06-15-14-30-22` | `Screenshot_2024-06-15-14-30-22.png`（全中划线） |
| 10. YYYY-MM-DD HH-MM-SS | `2015-12-04 15-39-11` | `2015-12-04 15-39-11-于果.jpg`（空格分隔） |

| 16. YYYYMMDD | `20220502` | `20220502（1）.mp4`、`20220502(1).mp4`、`20220502.mp4` |

> **date-only 模式**（13、14、16）：仅提取到日期时，时分默认设为 `0000`。

### 模式排序规则（重要：避免被意外截获）

模式匹配按 **JSON 数组中的出现顺序** 执行。代码遍历模式列表，对每个模式用 `finditer()` 扫描文件名中的所有匹配位置，**一旦找到一个合法的日期就立即返回**，不再继续尝试后续模式。

这意味着：**如果宽泛的模式排在精确模式前面，它会"截获"本应被后面精确模式匹配的文件名，导致时分信息丢失。**

#### 核心规则

| 规则 | 说明 |
|------|------|
| **精度优先** | 6 组（秒级）> 5 组（分级）> 3 组（日期级）。精确的模式必须排在模糊的模式之前 |
| **自有格式置顶** | `is_own_output: true` 的模式（ID 1-4）排在所有模式最前面，使用 `^...$` 完整锚定，确保已重命名文件被精确识别 |
| **分隔符区分** | 同精度下，分隔符特征越独特越靠前 |

#### 实例说明：为什么模式 17 必须在模式 14 前面？

```
文件名: 2016-04-03-20h52m50 -于果.JPG

❌ 如果把模式14 (YYYY-MM-DD) 放在模式17 (YYYY-MM-DD-HHhMMmSS) 之前：
  → 模式14 先匹配到 "2016-04-03" → 提取 2016-04-03 00:00:00（时分秒丢失！）

✅ 正确排列：模式17 在前，模式14 在后：
  → 模式17 匹配到 "2016-04-03-20h52m50" → 提取 2016-04-03 20:52:50
  → 模式14 永远不会被尝试（模式17 已成功）
```

#### 当前 18 个模式的正确排列顺序

```
[自有输出格式]  ← 精确锚定，最先匹配
  ID 1:  YYYY.MM.DD_HHMMSS        (6组, ^...$)
  ID 2:  YYYY.MM.DD_HHMM          (5组, ^...$)
  ID 3:  YYYY-MM-DD_HH-MM-SS      (6组, ^...$)
  ID 4:  YYYYMMDD_HHMMSS          (6组, ^...$)  ← 自有格式结束

[外部 6 组精确模式]  ← 时分秒完整
  ID 5:  YYYYMMDD_HHMM            (5组)
  ID 6:  YYYY-MM-DD_HHMMSS        (6组)
  ID 7:  YYYY-MM-DD_HHMM          (5组)
  ID 8:  YYYYMMDD-HHMMSS          (6组)
  ID 9:  YYYY-MM-DD-HH-MM-SS      (6组)  ← 全中划线
  ID 10: YYYY-MM-DD HH-MM-SS      (6组)  ← 空格分隔
  ID 11: YYYY_MM_DD_HHMMSS        (6组)  ← 全下划线
  ID 17: YYYY-MM-DD-HHhMMmSS      (6组)  ← h/m 标记
  ID 18: YYYY-MM-DD-HHMMSSmmm     (6组)  ← 毫秒后缀
  ID 15: YYYYMMDDHHMMSS           (6组)  ← 全紧凑型，放最后因为它是纯数字，误匹配风险最高

[5 组/3 组低精度模式]  ← 只有日期+分或纯日期
  ID 12: YYYY年MM月DD日 HH点MM分   (5组)
  ID 13: YYYY.MM.DD               (3组)  ← date-only
  ID 14: YYYY-MM-DD               (3组)  ← date-only，放最后因为它和所有中划线模式的前缀重叠
  ID 16: YYYYMMDD                 (3组)  ← date-only
```

#### 新增模式的插入自查清单

在 `patterns.json` 或 `_DEFAULT_PATTERNS_CONFIG` 中添加新模式时，按以下步骤确认插入位置：

1. **这是自有输出格式吗？** → 插入到 ID 4 之后、ID 5 之前，并设 `is_own_output: true`
2. **group_count 是多少？** → 按优先级段插入：
   - 6 组：插入"外部 6 组精确模式"段（ID 5-15 之间）
   - 5 组：插入"外部 5 组"段（紧接 6 组之后）
   - 3 组：插入"date-only"段末尾
3. **是否与已有模式的正则存在前缀重叠？** → 如果新模式的正则是某已有模式的子集（如 `YYYY-MM-DD` 是 `YYYY-MM-DD-HHhMMmSS` 的前缀），新模式必须排在已有模式**之后**
4. **添加后运行回归测试**：`python photo_renamer.py -s "测试" -m preview`，确认 58/58 无回归

> 一个简单的心智模型：**"能匹配到更精确时间的模式更靠前"**。6 组 > 5 组 > 3 组，同组内特征越独特越靠前。

## Unix 时间戳支持（优先级 3）

| 类型 | 位数 | 文件名案例 |
|------|------|-----------|
| 毫秒级 | 13 位 | `mmexport1664505286518.mp4`、`wx_camera_1718166753538.jpg` |
| 秒级 | 10 位 | 较少见，同样兼容 |

> **防误判**：32 字符以上的哈希文件名（如 `2d204843ed04114377f24af0c49045cb.jpg`）不会被误匹配为时间戳。

## 冲突处理机制

同一目录下，多个文件映射到相同 `YYYY.MM.DD_HHMM` 时：

- ~~旧逻辑：加序号后缀 `_1020(2).jpg`、`_1020(3).jpg`~~（v1.1 废弃）
- **v1.1+ 逻辑**：分钟自动递增（`_1020` → `_1021` → `_1022`）

**级联保护**：如果递增后的 stem 已被其他文件占用，继续递增直到唯一——例如 `1258` 和 `1259` 同时冲突时，第三个文件会跳过 `1259` 直接分配到 `1300`。

## 使用方法

### CLI 参数

```
python photo_renamer.py -s <源文件夹> [选项]

选项:
  -s, --source     源文件夹路径（必需）
  -m, --mode       模式: preview(预览) / execute(执行)
  -r, --recursive  递归处理子目录
  -f, --format     输出格式，预设名或自定义 strftime
  -o, --output-dir 输出目录（复制模式），不指定则原地重命名
  --csv            预览模式导出 CSV 路径（默认: preview_report.csv）
  -e, --ext        限制扩展名，逗号分隔，如 ".jpg,.mp4"
  -F, --force      强制执行，跳过"已重命名目录"检查
```

### 输出格式预设

| 预设名 | Python 格式 | 示例输出 |
|--------|-------------|----------|
| `默认` | `%Y.%m.%d_%H%M` | `2026.05.26_1021.jpg` |
| `精确到秒` | `%Y.%m.%d_%H%M%S` | `2026.05.26_102130.jpg` |
| `中划线分隔` | `%Y-%m-%d_%H-%M-%S` | `2026-05-26_10-21-30.jpg` |
| `紧凑型` | `%Y%m%d_%H%M%S` | `20260526_102130.jpg` |

也支持自定义 Python strftime 格式，例如 `"%%Y年%%m月%%d日_%%H时%%M分"`（Windows cmd 下 `%` 需双写）。

### 快速示例

```bash
# 预览当前文件夹（不改文件，输出对照表 + CSV）
python photo_renamer.py -s "D:\照片" -m preview

# 预览 + 递归子目录 + 精确到秒格式
python photo_renamer.py -s "D:\照片" -m preview -r -f "精确到秒"

# 执行重命名（原地修改）
python photo_renamer.py -s "D:\照片" -m execute

# 复制到 output 目录（原文件不动）
python photo_renamer.py -s "D:\照片" -m execute -o "D:\已整理"

# 只处理 .jpg 和 .mp4
python photo_renamer.py -s "D:\照片" -m preview -e ".jpg,.mp4"

# 强制执行（已重命名过的目录需加 --force）
python photo_renamer.py -s "D:\照片" -m execute --force
```

### 重复处理保护

当目录中检测到文件已被本工具重命名过时：

- **预览模式**：显示警告 ⚠，但仍正常运行（方便检查）
- **执行模式**：自动中止 ⛔，要求使用 `--force` 确认

这是为了防止视频文件因缺少 EXIF、回退到文件名解析时分会丢失（如 `2025.06.30_1402.mp4` 被重新解析为 `2025.06.30_0000.mp4`）。

```bash
# 场景：目录已处理过，需要重新整理
python photo_renamer.py -s "D:\已整理" -m preview     # 先预览，检查结果
python photo_renamer.py -s "D:\已整理" -m execute --force  # 确认无误后执行
```

### launch.bat 交互式菜单

将 `launch.bat` 和 `photo_renamer.py` 放在同一目录，双击运行：

```
[1] 预览 - 单个文件夹
[2] 预览 - 含所有子文件夹
[3] 执行 - 单个文件夹（直接重命名）
[4] 执行 - 含所有子文件夹（直接重命名）
[5] 自定义参数运行
[6] 智能发现 - 扫描潜在日期格式
[0] 退出
```

> `launch.bat` 为 GBK 编码，包含中文菜单。在 Windows 简体中文系统上直接双击即可正常显示。

**v2.1 新增**：选项 [3]/[4] 执行时，若检测到目录含已重命名文件，bat 会自动询问"是否强制继续？"，输入 `yes` 后自动追加 `--force` 重新执行，无需手动输入完整命令。

### 模式配置文件（patterns.json）

v2.0 起，日期识别模式改为外部 JSON 配置，支持手动编辑：

```json
{
  "version": "2.0",
  "patterns": [
    {
      "id": 16,
      "regex": "(\\d{4})(\\d{2})(\\d{2})",
      "group_count": 3,
      "description": "YYYYMMDD（纯8位日期，如 20220502（1））",
      "is_own_output": false
    }
  ]
}
```

**字段说明**：
- `regex`：Python 正则表达式，捕获组必须按 年/月/日/时/分/秒 顺序
- `group_count`：3 = 仅日期，5 = 日期+时分，6 = 日期+时分秒
- `is_own_output`：`true` 表示该格式用于"已重命名"检测
- **添加新模式**：在 `patterns` 数组中插入 JSON 条目，按优先级排列（精确的在前）

**管理命令**：
```bash
# 生成默认配置文件
python photo_renamer.py --generate-config

# 使用自定义配置文件
python photo_renamer.py -s "D:\照片" -m preview --pattern-config "D:\my_patterns.json"
```

### 智能模式发现（`--discover`）

自动扫描未匹配文件，检测潜在日期格式，生成建议 JSON 条目：

```bash
# 扫描目录，发现未知日期格式
python photo_renamer.py --discover -s "D:\照片" -r

# 导出发现报告
python photo_renamer.py --discover -s "D:\照片" -r --csv discover.csv
```

工作流程：
1. 先用现有 18 种模式匹配，统计覆盖率
2. 对未匹配文件用启发式算法扫描（Y-M-D / D-M-Y / 紧凑型 / 混合分隔符）
3. 按模式签名分组展示，标注歧义格式 ⚠
4. 自动生成建议的 JSON 配置条目
5. 导出 CSV 供人工核对

**核查无误后**，将建议条目复制到 `patterns.json` 的 `"patterns"` 数组中，重新运行即可识别。

## 网络盘（群晖 NAS）使用

本工具针对网络盘场景做了特殊适配：

- **I/O 超时保护**：所有文件操作（EXIF 读取、stat、复制、重命名）均带超时，默认 15 秒
- **自定义超时**：通过环境变量调整

```cmd
# 网络较慢时可增大超时（单位：秒）
set PHOTO_RENAMER_TIMEOUT=30
python photo_renamer.py -s "\\NAS\照片" -m preview

# PowerShell
$env:PHOTO_RENAMER_TIMEOUT = "60"
python photo_renamer.py -s "\\NAS\照片" -m preview
```

- **进度条超时计数**：运行时可看到 `⏱超时:N`，了解有多少文件因网络延迟被跳过
- **渐进式 EXIF**：只读取文件头部 256KB，绝大多数情况下已包含 EXIF，避免大文件下载

## 代码架构

### 核心类职责

| 类/函数 | 职责 | 关键特性 |
|---------|------|---------|
| `DateExtractor` | 日期提取引擎 | 4级优先级链，纯类方法，延迟加载模式 |
| `PatternDiscoverer` | 智能模式发现 | 6阶段启发式扫描，支持泛化分隔符/时间戳/App前缀 |
| `PhotoRenamer` | 重命名引擎 | 扫描、冲突处理（分钟递增+级联保护）、CSV导出 |
| `ProgressBar` | 终端进度条 | 零依赖，`\r` 原地刷新，非交互模式逐行输出 |
| `run_with_timeout()` | 超时保护 | ThreadPoolExecutor，默认15s，环境变量配置 |

### 设计原则

- **核心逻辑与 CLI 彻底分离**：`PhotoRenamer` 类可直接被 GUI 调用，不依赖 argparse
- **配置外部化**：日期模式在 `patterns.json` 中编辑，即改即生效，无需改代码
- **零依赖核心**：Pillow 是唯一可选依赖，缺失时 EXIF 不可用但其他功能完全正常
- **网络盘友好**：全链路超时保护 + 渐进式 EXIF 读取（256KB→1MB）
- **单文件架构**：整个项目 1 个 Python 文件，复制即用

## 注意事项

- **预览优先**：建议始终先跑 `preview` 模式，确认结果无误后再执行
- **扩展名统一小写**：所有输出文件扩展名强制转为小写（如 `.JPG` → `.jpg`）
- **视频 EXIF**：视频文件不通过 Pillow 读取元数据，日期依赖文件名或时间戳
- **HEIC 支持**：需要 `pillow-heif` 插件，见"安装依赖"章节
- **年份范围**：有效性检查限定 1970-2099，避免误匹配
- **bat 编码**：`launch.bat` 为 GBK 编码，在非中文 Windows 上菜单可能乱码，但不影响功能——直接用 CLI 即可
- **重复处理**：对已重命名的目录重新执行需加 `--force`，防止视频时分信息被错误修改
- **Pillow 降级**：未安装 Pillow 时图片 EXIF 不可用，但文件名/时间戳提取功能完全正常
